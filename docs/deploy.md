# Deploying to Render (owner checklist)

Nothing here runs automatically. The first deploy needs a `git push` to GitHub, which only happens when the owner approves it in chat.

## 1. MongoDB Atlas
- Network Access → add `0.0.0.0/0` (Render free has no static IP — planning §6). This exposes the cluster to the internet behind the password, so:
- Use a database user with a **long random password** and only `readWrite` on `irminsul_prod` and `irminsul` (the model files live in `irminsul`, see the lock file). No Atlas admin role.

## 2. Model files (already done once)
The ONNX model is git-ignored. `scripts/upload_model.py` stored it in GridFS (`irminsul.model_files`) and wrote `ai/model_cards/plantvillage-mobilenetv2.lock.json`, which pins every file's SHA-256. The Render build runs `scripts/download_models.py`, which fails the build if any file is missing or altered.

## 3. Production data
Seed the production database from this laptop (same Atlas cluster):

```bash
MONGODB_DB=irminsul_prod uv run python -I scripts/seed.py
```
Demo accounts use `SEED_DEMO_PASSWORD`; set the same value in Render. The mandi snapshot loads itself on first start.

## 4. Render
1. New → Blueprint → select the GitHub repo (render.yaml is picked up).
2. Enter the `sync: false` values: `MONGODB_URI`, `DATA_GOV_IN_API_KEY`, `SEED_DEMO_PASSWORD`, `PUBLIC_BASE_URL` (fill in after the first deploy shows the URL, then redeploy).
3. `JWT_SECRET` is generated by Render; `ENVIRONMENT=production` turns on Secure cookies and HSTS.

## 5. After deploy
- Open `/api/v1/health` → `{"status": "ok", "db": "ok"}`.
- Free instances sleep when idle: open the URL a few minutes before a demo (planning §15).
- Check the QR verify page from a phone (demo story step 8).
